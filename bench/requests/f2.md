Feature: invoice refunds for ledger-lite (payments from the previous feature are in the code).

Staff refund money that a customer already paid.

1. `recordRefund(invoiceId, amount, reason)` in `src/invoices.js`. `amount` is a baht string such as "100.50"; `reason` is free text. It returns the updated invoice.
2. An invoice keeps `refunds` (an array of satang amounts, oldest first) and `refundedSatang` (their sum). A refund may not take `refundedSatang` above `paidSatang`.
3. When `refundedSatang` equals `paidSatang` and `paidSatang` is above 0, the status becomes REFUNDED. Otherwise the status stays as it was.
4. Errors, by `err.code`: NOT_FOUND for an unknown invoice; BAD_AMOUNT as for payments; BAD_REASON when `reason` is not a non-empty string; OVER_REFUND when the refund would exceed what is paid and not yet refunded. A rejected refund changes nothing.
5. `netPaidSatang(invoice)` is exported from `src/invoices.js` and returns `paidSatang` minus `refundedSatang`.
6. A refund follows the same concurrency rule as a payment: it must never overwrite another clerk's change.
